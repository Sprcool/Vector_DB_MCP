CONTEXT

Why RAG?

Language models are fluent, not omniscient. Retrieval-augmented generation closes the gap between what a model was trained on and what it actually needs to know to answer correctly.

!Why LLMs hallucinate

A model's knowledge is frozen at training time and compressed into weights — it has no way to look anything up. When a question falls outside what it memorized (a private document, a recent change, a specific brochure), it still produces a fluent answer, just not necessarily a true one.

⌕Why retrieval is needed

Retrieval gives the model an open book instead of asking it to answer from memory. Relevant passages are fetched at query time and placed directly in front of the model, so the answer is grounded in something real and checkable rather than reconstructed from training statistics.

✓How this project solves it

Vector_DB_MCP turns a source PDF into searchable, semantically-chunked passages in ChromaDB. At query time, the closest passages are retrieved by meaning (not keyword) and served through an MCP tool, so any MCP-aware client can ground its answers in the source document.

≈Benefits of semantic search

Embedding-based search matches on meaning, not exact wording — a question phrased differently from the source text still finds the right passage. Combined with heading and page metadata, results stay traceable back to exactly where they came from.

STACK

Technology stack

A short summary — the full write-up with rationale for each choice lives on the architecture page.

PyPython

Glue language for the whole pipeline — every stage is a small, typed, composable module.

DcDocling

Parses PDFs into a structured document and hierarchically chunks it along real section boundaries.

STSentence Transformers

Runs BAAI/bge-base-en-v1.5 locally to turn text into 768-dimensional embeddings.

CrChromaDB

Persistent local vector store — one collection, upsert on ingest, cosine query on retrieval.

McFastMCP

Exposes retrieval as a single MCP tool so any MCP-aware client can query the knowledge base.

#SHA-256

Derives a deterministic chunk id from source + page + heading + text, enabling idempotent upserts.
