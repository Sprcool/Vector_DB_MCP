Pipeline

The nine RAG pipeline stages

Every stage narrows or transforms one shape into the next — a PDF becomes a document, a document becomes chunks, chunks become records, records become vectors, vectors become a searchable index, and a question becomes a grounded answer.

01

Document Ingestion config.py

The entry point for the whole batch process. KNOWLEDGE_BASE resolves two directories up from config.py, anchoring the pipeline to a project root that holds PDF_Source/ and Vector_DB/ as siblings — everything downstream reads from these fixed paths.

PDF_PATH        = KNOWLEDGE_BASE / "PDF_Source" / "AZURE_DATA_ENGINEERING_BROCHURE.pdf"
EMBEDDING_MODEL = "BAAI/bge-base-en-v1.5"
VECTOR_DB_PATH  = KNOWLEDGE_BASE / "Vector_DB"
COLLECTION_NAME = "vector_db_mcp"
02

Document Parsing document_parser.py

Wraps Docling's DocumentConverter. Validates the PDF exists before conversion and returns Docling's structured DoclingDocument — headings, page provenance, and layout are preserved for later stages to read back out.

def load_document(pdf_path: Path):
    # raises FileNotFoundError early if the PDF is missing
    converter = DocumentConverter()
    result = converter.convert(pdf_path)
    return result.document
03

Semantic Chunking chunker.py

Delegates to Docling's HierarchicalChunker, which splits the parsed document along its structural boundaries (sections/headings) rather than fixed token windows — chunks stay semantically coherent, which is what makes the retrieved context useful later.

chunker = HierarchicalChunker()
chunks  = list(chunker.chunk(document))
04

Metadata Mapping chunk_mapper.py

Flattens each Docling chunk into a plain KnowledgeRecord: text, joined heading breadcrumb ("A > B > C"), first page number from provenance, and source filename. The record's id is a SHA-256 hash of source|page|heading|text — deterministic, so re-ingesting the same PDF regenerates identical ids.

value = f"{source}|{page}|{heading}|{text}"
id    = hashlib.sha256(value.encode("utf-8")).hexdigest()
05

Deduplication deduplicator.py

Collapses records into a dict keyed on record.id, so any two chunks that hash identically are merged into one. Because the id is content-derived, this doubles as idempotency for re-runs, not just noise removal.

unique_records = {r.id: r for r in records}
print(f"Removed {before - after} duplicate chunks")
06

Embedding Generation embeddings.py

EmbeddingService loads BAAI/bge-base-en-v1.5 once and exposes two paths: batch .embed() for ingestion, and single-string .embed_query() for retrieval. Each ingested record is paired with its 768-dimension vector into an EmbeddedKnowledgeRecord.

vectors = self.model.encode(texts)                      # document side
embedding = self.model.encode(query, normalize_embeddings=True)  # query side
07

Vector Indexing vector_store.py

VectorStore owns the only connection to ChromaDB — a PersistentClient rooted at config.VECTOR_DB_PATH. .store() upserts ids, documents, metadata (heading/page/source), and embeddings in one call; .reset() drops and recreates the collection.

self.collection.upsert(
    ids=ids, documents=documents,
    metadatas=metadatas, embeddings=embeddings
)
08

Semantic Retrieval retrieval_service.py

The entry point external callers use for search. It composes EmbeddingService.embed_query() and VectorStore.search(), returning ranked SearchResult objects with cosine distance alongside the original heading/page/source metadata.

query_embedding = self.embedding_service.embed_query(question)
results = self.vector_store.search(query_embedding, top_k)
return results
09

MCP Integration mcp_server.py

Wires the pipeline into an MCP server. A single FastMCP instance named "Knowledge Base" builds one shared EmbeddingService / VectorStore / RetrievalService at import time, then exposes search_knowledge_base(question, top_k) as the only tool — results are converted from SearchResult dataclasses to plain dicts with asdict() before crossing the MCP boundary to any connected client.

@mcp.tool()
def search_knowledge_base(question: str, top_k: int = 5):
    results = retrieval_service.search(question, top_k)
    return [asdict(result) for result in results]
