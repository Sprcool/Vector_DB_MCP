System design

End-to-End RAG Architecture

Two flows share one store, and the retrieval flow terminates in an MCP tool. The ingestion flow (top) runs offline to populate the collection; the retrieval flow (bottom) runs per-query and is exposed to any MCP client through a single FastMCP tool.

DESIGN

Design principles

The choices that shape every module, not just the obvious ones.

#Deterministic IDs

Chunk ids are a SHA-256 hash of source, page, heading, and text — the same input always produces the same id.

↻Idempotent ingestion

Re-running ingestion on an unchanged PDF re-derives the same ids, so upsert() overwrites in place instead of duplicating.

▦Modular architecture

Parsing, chunking, mapping, deduplication, embedding, storage, and retrieval are each a single-purpose module with one job.

⊘Separation of concerns

VectorStore is the only module that talks to ChromaDB; EmbeddingService is the only one that loads the model. Nothing else knows how they work internally.

⇄Stateless retrieval

RetrievalService.search() holds no state between calls — every query is embedded and searched fresh, so concurrent queries can't interfere with each other.

◧Metadata preservation

Heading breadcrumbs and page numbers survive from the original PDF all the way to the final SearchResult, so answers stay traceable to their source.

τStrong typing

Every record that moves between stages is a typed dataclass — KnowledgeRecord, EmbeddedKnowledgeRecord, SearchResult — not a loose dict.

+Extensibility

Swapping the embedding model, the vector database, or the document source means touching one module, not rewriting the pipeline.

STACK

Technology stack

What each dependency is responsible for, and why it's the one used here.

TechnologyRole
PythonLanguage for the whole pipeline — typed dataclasses and small composable modules end to end.
DoclingConverts a PDF into a structured document and chunks it along real section/heading boundaries via HierarchicalChunker.
Sentence TransformersRuns the embedding model locally through a simple .encode() API, for both batch document embedding and single-query embedding.
BAAI/bge-base-en-v1.5The specific embedding model — a 768-dimension general-purpose English sentence embedding model, strong on retrieval tasks.
ChromaDBPersistent local vector database. One PersistentClient, one collection, upsert on ingest, cosine query on retrieval.
FastMCPWraps RetrievalService as an MCP tool (search_knowledge_base) so any MCP-aware client can call it directly.
SHA-256Hashes source|page|heading|text into a deterministic chunk id, the basis for idempotent re-ingestion.
DataclassesTyped, structured records (KnowledgeRecord, EmbeddedKnowledgeRecord, SearchResult) instead of untyped dicts moving through the pipeline.
